# Live agent view

Open **MENU > AGENTS**. Read-only: it consumes the separate USB live snapshot and never changes quotas, issues provider commands or approves tools.

![Native LVGL agent view with synthetic data](images/device-agents-readable.png)

## What is shown

| Element | Behavior |
| --- | --- |
| Rows | 4 per page: provider, shortened opaque session ID, last reported state. At most 8 entries published (not the provider's total agent count). |
| Provider-status rows | For selected providers without recent live sessions. From quota/token availability; never create live agents. Codex/Claude/ZCode: NO RECENT EVENTS; others: ACTIVITY ONLY. Up to 8 sessions and 8 statuses, counted separately. |
| States | WAITING and FAILED use text and color. UNKNOWN = phase not reported. DONE = turn stopped, not proof a task or tests succeeded. |
| Summary line | e.g. "1 error / 2 need you / 2 working", colored by the most urgent. Page label shows the real total ("8 of 11"). |
| Row chip and name | Derived from the session ID (same in the PC terminal); recognition aid only. |
| Empty list | Names providers not yet linked to LimitBuddy. |
| Timers | Observed turn/subagent duration when a start exists, plus explicit last-event age; unknown starts are labelled. |

Navigation: MENU, HOME and NEXT PAGE stay fixed; NEXT PAGE hides with one page. A new transport epoch or fewer entries returns to page one; hidden rows have text cleared. After 30 s without a valid USB update entries disappear and setup/reconnect guidance shows. Shell commands are never inspected to guess testing/building, and a readable token counter does not establish a working phase.

## Needs-you banner

A fresh WAITING or NEEDS ATTENTION event raises a banner on other screens and wakes a dimmed display once per request; DISMISS silences that request only. Old events and stale feeds never raise it; the Agents screen itself shows no banner.

## Phases and timers

Metadata capability 2 adds WORKING, READING, WRITING, RUNNING, NEEDS_ATTENTION, ERROR and COMPLETED to the generic agent state model. Older firmware receives downgraded three-field metadata. NOVA reacts only to recent explicit client events; provider session counts are not counted twice.
